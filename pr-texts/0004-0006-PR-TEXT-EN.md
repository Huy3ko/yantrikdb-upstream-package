# Belief evidence: identity, propagation, and time (three commits)

Three defects in the same path — how evidence reaches a belief's `log_odds`.
They are one PR because two of them do not build alone: 0005 uses the identity
field 0004 introduces, and 0006 uses the propagation origin 0005 introduces.

## Commit 1 — `fix(belief): stable observation identity`

**Defect.** `assert_evidence` had no notion of *what* was observed. Every call
appended a trail entry and added to `log_odds`:

```rust
pub fn update(&mut self, weight, reliability, source: &str, timestamp: f64) {
    let effective_weight = weight * reliability;
    self.log_odds += effective_weight;                 // always add
    self.evidence_trail.push(EvidenceEntry { … });     // always append
}
```

A retry, a replayed turn, or a re-extracted memory doubles the confidence.
Measured: same evidence asserted twice → **0.9000 → 1.8000**.

**Change.** `Evidence` and `EvidenceEntry` carry an optional `observation_id`;
`update_with_id` revises when the id is already present:
`log_odds += (new_eff − old_eff)`, the trail keeps ONE entry, the original
timestamp stays, and the earlier assessment is kept in `history`.

## Commit 2 — `fix(belief): propagated evidence keeps one voice`

**Defect.** `propagate_evidence` added the damped weight straight onto the
target's `log_odds`: no trail entry, no identity. The same edge traversed twice
counted twice, and a diamond (one origin, two intermediate beliefs) counted
twice on the far side. Measured: same edge twice → **0.5000 → 1.0000**.

**Change.** A propagated entry carries its origin
(`observation_id = "prop|<origin>|<origin-rid>"`) and the individual paths that
carried it (`paths: Vec<(NodeId, weight)>`). `weight` stays the aggregate the
belief uses — the strongest live path — so withdrawing one path promotes the
next instead of erasing the effect.

## Commit 3 — `fix(belief): staleness decay depends on elapsed time`

**Defect.** `apply_staleness_decay` multiplied the **running** value by a factor
it recomputed from the same evidence timestamp on every call. A maintenance loop
that runs `revise_beliefs` once per turn subtracts the same elapsed period again
and again. Two regression tests carrying the measurements were in the tree with
`#[ignore]`.

**Change.** `BeliefPayload` gains `undecayed_log_odds` (`#[serde(default)]` for
existing rows). Decay is recomputed from that anchor, never from an
already-decayed value, so the same instant yields the same result regardless of
how often the pass ran. Verified: three calls at the same `at` → identical
value, anchor unchanged.

## Tests

Per commit, in `cognition/belief.rs` and `engine/tests/`:
identity (repeat revises, different ids accumulate), propagation (one voice
across paths, diamond counted once, withdrawal promotes the next path), decay
(the two previously `#[ignore]`d tests, now active, plus idempotency at a fixed
instant).

Series against `main` = `bee011a`: **2,307 passed, 0 failed** (6 ignored).
0004 also builds and passes **alone** (2,293 / 0); 0005 and 0006 do not, and are
marked as depending on their predecessor.

## Not included

- No Python binding change in this PR — `0007` (native belief lifecycle over
  Python) is prepared separately and depends on all three commits.
- No confidence ceiling or `max_abs_log_odds` change.
- No migration of existing rows: `undecayed_log_odds` is `NULL` for them and
  the code falls back to the current value on the first decay pass.
