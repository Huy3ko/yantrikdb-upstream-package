## What this changes

`check_redundancy_in_namespace` used to call `check_substitution_category_pair`
for every pair of near-duplicate memories above the threshold. That helper runs
**one JOIN query per token pair** of the two texts' symmetric difference:

```sql
SELECT c.name FROM substitution_members m1
  JOIN substitution_members m2 ON m1.category_id = m2.category_id
  JOIN substitution_categories c ON c.id = m1.category_id
 WHERE m1.token_normalized = ?1 AND m2.token_normalized = ?2
   AND m1.status = 'active' AND m2.status = 'active'
   AND m1.confidence >= 0.6 AND m2.confidence >= 0.6
   AND c.status = 'active' AND c.conflict_mode = 'exclusive'
 LIMIT 1
```

Two texts of a few thousand characters differ in hundreds of tokens each, so a
single memory pair costs tens of thousands of round trips — against a table that
held **8 categories and 80 members** on the store where this was measured.

This PR loads that table **once per namespace** into a map
(`token -> [(category_id, category_name)]`, filtered with exactly the same
predicate) and answers the same question in memory.

**No cognition operation is disabled, gated or skipped.** The trigger still
fires, the conflict is still persisted, the same pairs are compared. Only the
lookup mechanism changed. (The one thing that *is* removed is a per-pair call
that held the connection lock inside an `if let` scrutinee — the deadlock hazard
that scoping existed for is gone, because no lock is taken per pair any more.)

## Measured

`crates/yantrikdb-core/examples/substitution_index_bench.rs` builds a store of
the shape that made this expensive (8 namespaces × 30 records, two near-duplicate
families per namespace, 1024-dim vectors) and times `check_redundancy` end to
end. Same harness, built from `3d52394` and from this branch:

```
parent (3d52394)        PERF_CHECK name=redundancy > 300 s (timeout after 300 s)
this branch             PERF_CHECK name=redundancy 1.242 s
```

On a production store of 24,268 records the same phase went from **not finishing
within 116 s** to **0.531 s with 32 triggers produced** (`examples/think_phases.rs`,
per-phase harness). `think()` as a whole dropped from >25 min to 2.01 s.

## Equivalence with the SQL reference

The SQL function is kept as the readable statement of the predicate
(`#[allow(dead_code)]`), and six tests compare both implementations side by side:

- single matching category — same category name and same token pair returned;
- **several categories matching the same pair** — both must find a match and both
  must name a category that really contains the pair. (Neither order is
  deterministic: the SQL `LIMIT 1` has no `ORDER BY`, the index walks a `HashMap`.
  Pinning a specific name here would be pinning an accident.)
- **different token positions** (head, middle, tail) — same answer;
- **rows the predicate must reject**: inactive member, `confidence < 0.6`,
  non-exclusive category, inactive category — both return `None`;
- tokens no category contains — both return `None`.

`cargo test --release -p yantrikdb --lib cognition::triggers::tests` → **29 passed, 0 failed**.

## Compatibility

- **#311 (redundancy gate)** applies cleanly; it touches `engine/cognition.rs`
  and does not overlap.
- **#312 (shared subject/frame)** touches `check_substitution_category_pair` and
  its two call sites — the ones this PR replaces. It needs a rebase, and the
  rebase is not mechanical: its subject/frame predicate must move **into**
  `check_substitution_pair_in_index`, otherwise applying it after this change
  edits a function the redundancy path no longer calls — green tests, no effect
  in production. Both functions already receive the two texts, so the move is
  small; the index only supplies the candidate set.
